✍️ Ask a Question
Students can post questions in two ways:
1. Through the Ask a Question option.
2. Through the Chatbot.
Process for Ask a Question:
• Student writes their description.
• Optionally uploads a screenshot.
• Selects a category (or “Other”).
• System checks:
	1. FAQs → If an answer exists, show it. Ask: “Does this answer your question?”
		▪︎ If no, allow posting the question.
	2. If answer doesn't exist in faq, Show top 2 unresolved queries that are similar to the current post student has written.
		▪︎ If student clicks “I have the same query,” their ID is tagged to the same question.
This way, moderators can respond collectively to similar queries.

### Student Analytics Page

Create a dedicated Analytics Page for Students to help them track their participation, contributions, and performance within the Community Q&A platform.

### Features to Include

#### Community Q&A Performance
Display analytics related to the student’s activity, including:
- Total number of Community Q&A questions answered
- Total accepted/helpful answers
- Participation trends and engagement statistics

#### Peer Ranking Section
- Add a sidebar section that displays the student’s rank compared to other peers.
- Rankings should be based on:
  - Number of Community Q&A answers contributed
  - Overall engagement and activity

#### Spurti Points Leaderboard
- Include a separate ranking module for Spurti Points.
- Students should be able to view:
  - Their current Spurti Points
  - Their rank among peers
  - A leaderboard of top-performing students based on Spurti Points

### Additional Enhancements
- Add filters such as:
  - Weekly
  - Monthly
  - Overall rankings
- Use cards, graphs, and leaderboard components for a clean and interactive UI.
- Ensure rankings and analytics update dynamically in real time or through scheduled refreshes.

### Goal
The Analytics Page should encourage healthy competition, increase student engagement, and motivate students to actively participate in the Community Q&A ecosystem.

Create a modular semantic search engine that can be attached to any backend route/service.

Architecture:

Main backend: Node.js
Semantic embedding service: Python FastAPI microservice
Database: Existing MongoDB
Cache: Redis
Queue: BullMQ
Requirements:

No paid APIs
No OpenAI/external AI calls
CPU-only
Low RAM usage
Very fast semantic similarity search
Production-ready
Modular and scalable
Multi-user support
Core Flow:

1.      Convert user question → embeddings
2.      Compare with Knowledge Base using cosine similarity

If found:
Show flash question + answer
Return similarity score + source type = knowledge_base
If not found:
Move to Community Search

3.      Compare with cached community questions (last 7 days)
·        If match found:
o    Show already answered/community question
o    Add current question to cached memory (count++)
o    Return source type = cached_question

·        If no match found:
o    Upload/save as new community question
o    Return "not found" or waiting for answer status
